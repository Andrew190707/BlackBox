Build a full-stack cybersecurity prototype called BlackBox — an Autonomous Cyber Governance, Containment, Deception & Recovery system. This is not a SIEM, not an EDR, not a DLP. It is a Cyber Governance Layer that sits above all existing security tools and governs access to critical assets.

TECH STACK

Backend: Python 3.11 + FastAPI
Frontend: React 18 + Tailwind CSS
Database: SQLite (via SQLAlchemy) for event logs and state
Real-time: WebSockets (FastAPI WebSocket) for live dashboard updates
AI/ML: scikit-learn (Isolation Forest for anomaly detection)
File monitoring: watchdog (cross-platform)
Process monitoring: psutil (cross-platform)
Package manager: pip for backend, npm for frontend
Project structure: monorepo — /backend and /frontend folders

BACKEND — DETAILED IMPLEMENTATION
1. Flight Recorder Engine (engines/flight_recorder.py)
Use watchdog to monitor a configurable directory (default: /tmp/blackbox_watch on Linux, C:\blackbox_watch on Windows — create it if it doesn't exist).
Monitor and log these event types to the events DB table:

FILE_ACCESS — file opened/read
FILE_CREATE — new file created
FILE_MODIFY — file modified
FILE_DELETE — file deleted
PROCESS_CREATE — new process started (use psutil process iter diff)
LOGIN — simulated login events (generate realistic fake ones for demo)

Each event must have:
python{
  "id": uuid,
  "timestamp": ISO datetime,
  "event_type": string,
  "user": string,
  "source": string,        # file path or process name
  "details": JSON string,  # extra metadata
  "risk_delta": float,     # how much this event affects risk score
  "threat_state": string   # GREEN / YELLOW / ORANGE / RED
}
Run the file watcher in a background thread using asyncio.run_in_executor. Broadcast every new event over WebSocket.
2. Behavioral Intelligence Engine (engines/behavioral_ai.py)
Use scikit-learn Isolation Forest to detect anomalies.
Maintain a sliding window of the last 200 events. Extract these features per event window:

events_per_minute — event rate
unique_files_accessed — distinct files touched
data_volume_mb — estimated bytes accessed (simulate if real data unavailable)
process_count — number of unique processes
hour_of_day — time-based feature

Train the Isolation Forest on first 50 events (warm-up period), then run predict() on each new event window.
Compute a Risk Score 0–100:
python# anomaly_score from IsolationForest ranges -1 to 1
# map to 0–100:
risk = max(0, min(100, (1 - anomaly_score) * 50))
# also add rule-based boosts:
# +30 if data_volume_mb > 500 in last 5 mins
# +20 if events_per_minute > 100
# +15 if LOGIN event at unusual hour (outside 8am–8pm)
Determine Threat State from risk score:

0–40 → GREEN
41–70 → YELLOW
71–90 → ORANGE
91–100 → RED

Expose current risk score and threat state via /risk/score endpoint. Broadcast changes over WebSocket.
3. Circuit Breaker Engine (engines/circuit_breaker.py)
Maintain 5 independent circuit breakers as state objects:
pythonBREAKERS = {
  "vpn":             {"status": "CLOSED", "tripped_at": None, "reason": None},
  "database":        {"status": "CLOSED", "tripped_at": None, "reason": None},
  "api_tokens":      {"status": "CLOSED", "tripped_at": None, "reason": None},
  "uploads":         {"status": "CLOSED", "tripped_at": None, "reason": None},
  "remote_sessions": {"status": "CLOSED", "tripped_at": None, "reason": None},
}
Status values: CLOSED (normal), TRIPPED (severed), RESET (manually restored).
Implement:

auto_trip(risk_score) — automatically trips breakers based on thresholds:

Risk > 70 → trip uploads and remote_sessions
Risk > 80 → also trip api_tokens
Risk > 90 → trip all breakers


manual_trip(name, reason) — operator can trip individual breakers
reset_breaker(name) — restore a single breaker
Every trip/reset is logged as an event and broadcast over WebSocket

4. Governance Engine (engines/governance.py)
Implement a simple policy engine with configurable rules:
pythonPOLICIES = [
  {"resource": "customer_db",    "allowed_users": ["admin", "analyst"], "max_volume_mb": 100},
  {"resource": "payroll_data",   "allowed_users": ["hr_admin"],          "max_volume_mb": 50},
  {"resource": "source_code",    "allowed_users": ["dev_lead", "admin"], "max_volume_mb": 500},
  {"resource": "executive_docs", "allowed_users": ["ceo", "cfo"],        "max_volume_mb": 10},
]
Evaluate each access request against policies and return ALLOW, WARN, or BLOCK. Log every decision as an event.
Maintain a User Trust Score per user (starts at 100, decreases on policy violations, increases over time with clean behavior). Store in SQLite.
5. BlackBox Lockdown Protocol (engines/lockdown.py)
Three-phase lockdown sequence. Expose as async function that runs the phases in order:
Phase 1 — Evidence preservation (calls state_preservation.py):

Trigger forensic snapshot immediately
Log: LOCKDOWN_PHASE1_COMPLETE

Phase 2 — Trust severance (calls circuit_breaker.py):

Trip ALL circuit breakers simultaneously
Disable all simulated external connections
Log: LOCKDOWN_PHASE2_COMPLETE

Phase 3 — Asset protection:

Set all monitored resources to READ_ONLY mode (update DB flag)
Deploy deception assets (calls deception.py)
Log: LOCKDOWN_PHASE3_COMPLETE

Store lockdown state in DB. Broadcast each phase completion over WebSocket so the dashboard updates in real time.

When triggered, collect and store a forensic snapshot:
python{

IMPORTANT REQUIREMENTS

Cross-platform: use os.path and pathlib everywhere. Never hardcode Linux-only paths. Use tempfile.gettempdir() for the watch directory base.
No real system damage: this is a prototype. File monitoring should only watch the designated blackbox_watch directory. Never touch system files. The "circuit breakers" are simulated state — they do not actually kill real network connections.
Auto-start: on Replit run, both backend (FastAPI on port 8000) and frontend (Vite dev server on port 5173) should start. Use a Procfile or replit.nix + shell script.
Seed data: on first startup, populate the DB with 50 realistic historical events so the dashboard is not empty. Include a few past incidents.
CORS: configure FastAPI CORS to allow requests from the Vite dev server.
Error handling: all API endpoints return proper HTTP status codes. WebSocket reconnects gracefully.
README.md: include setup instructions, architecture overview, and how to run the attack simulation demo.
